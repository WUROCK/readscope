# 手动书籍的完成状态与快捷更新

原问题有两处：后端按真实页数计算了 finished，但完整在读页没有排除完成项；进度四舍五入会让 319/320 页显示为 100%，使未完成状态显得矛盾。

现在未完成进度最多为 99%，到末页才显示 100%。完成项从在读列表、计数、排序和简洁摘要中移出，保留在下方可折叠的“已读完”书单。两种来源的书籍都按 finished 分类；手动书还会按页数重新核对状态，以兼容旧的状态标记。改小当前页会重新回到在读。不会删除个人记录。

添加时只需书名和总页数；当前页可不填，默认 0。书名后的 Enter 会聚焦总页数，再按 Enter 可提交。作者和领域是可展开的补充信息；封面自动显示书名首字，不增加上传步骤。

更新时默认只展示书籍摘要和当前页；页码自动选中，输入后 Enter 保存。+10/+20 与标记读完按钮直接保存，增加页数最多到末页。按钮旁明确提示会保存；保存期间阻止重复提交，失败保留表单和错误提示。需要改书名、总页数、作者或领域时展开编辑书籍信息。

完成反馈使用本次 API 返回的书籍立即更新列表，减少额外获取整份书单的请求。原来的自动标签、手动排序、透明度与窗口动画继续使用原有机制。

验证：类型检查和生产构建通过；12 项书籍服务及前端排序/分类检查通过；20 项纸质书真实 Electron 界面流程通过；另有 30 项既有界面检查通过。测试覆盖只填必填项、Enter 导航、进度自动选中、99% 边界、快捷累加到末页、完成归档、改小页数恢复、元数据编辑、重新加载持久化与简洁摘要跳过完成项。

运行 npm run test:ui:books 可复查，结果在 artifacts/manual-books-qa/summary.json。
